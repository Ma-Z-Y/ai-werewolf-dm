02 / SINGLE PLAYER

一个人，也能立刻开局

单人版保留完整 12 人局、警长竞选和赛后颁奖。默认使用本地规则 AI， 想接大模型时再打开配置。

不等待
点开新游戏就能进入夜晚，不需要等朋友上线。
不丢局
每次推进自动落盘，切后台或关页面后可以继续。
不离线失效
首次加载后注册 PWA，断网也能重新打开牌桌。

03 / SIX PLAYERS

六个真人，一个不会篡改规则的 AI

AI DM 不补位、不替玩家推理。它只负责推动阶段、执行规则、 隔离私密信息和保存可恢复的对局状态。

01 02 03 04 05 06 AI DM

主持人开房，朋友扫码入座

每个玩家获得独立座位令牌。公共屏、玩家手机和主持人审计分别使用不同的信息投影。

CORE

所有状态变化都经过规则核心

AI 不拥有状态，也不能跳过 apply_command() 修改游戏。

VIEW

公共、座位、主持三层投影

跨座位订阅直接拒绝，隐藏事实不会进入共享屏。

RECOVER

服务器重启后还能回到牌桌

房间、令牌、事件和恢复审计写入 SQLite，原凭据可以重连。

05 / RUN LOCALLY

朋友局只要一条命令

单容器同时提供 React 前端、FastAPI、WebSocket 和 SQLite 数据卷。 玩家只需要打开邀请链接。

docker compose up -d --build

临时公网访问可用 Cloudflare Tunnel，固定域名建议搭配 HTTPS 反向代理。

06 / OPEN SOURCE

两种模式，两条清晰的技术边界

单人版是基于上游 MIT 项目的独立静态应用；六人朋友局是 Apache-2.0 规则核心与实时服务。两者共用产品入口，不强行合并运行时。

SOLO / MIT

浏览器里的完整牌桌

solo/
  src/game/     规则引擎
  src/ai/       离线规则 AI
  src/render/   Three.js 场景
  public/       PWA 与离线缓存
PARTY / APACHE-2.0

手机与共享屏的实时房间

backend/
  domain/       状态机与投影
  application/  房间与恢复
  interfaces/   HTTP / WebSocket
frontend/
  player/ host/ stage/
